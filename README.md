# МФ_МодификацияФорм

Общий модуль 1С:Предприятие 8 для программного создания реквизитов и элементов управляемой формы.

Один файл `src/МФ_МодификацияФорм.bsl`. Копируется в общий модуль конфигурации, существующего расширения или нового расширения — зависимостей нет, БСП не нужна.

**Платформа: 8.3.10 и выше, включая 8.5.** Проверено на 8.3 и 8.5.

## Использование

Использовать можно в любых проектах, в том числе в закрытых коммерческих: без согласований и выплат. Менять, встраивать в свои продукты, распространять, продавать. Условие одно — сохранить блок уведомления об авторских правах в шапке модуля. Подробности и полный текст — [LICENSE](LICENSE).

## Зачем модуль

Программная модификация типовых форм переживает обновления конфигурации лучше, чем перенос элементов в редакторе расширения. Платформенный API при этом разбросан: `РеквизитФормы`, `ИзменитьРеквизиты`, `Элементы.Добавить/Вставить`, `Команды.Добавить`, и свойства, которых у одного поля много десятков. Модуль собирает это в предсказуемый набор методов и закрывает типовые грабли.

## Установка

1. Создать общий модуль с именем `МФ_МодификацияФорм`.
2. Свойства: **Сервер = Истина**, остальные — Ложь.
3. Вставить текст `src/МФ_МодификацияФорм.bsl`.

Модуль не требует правки при установке: префикс создаваемых объектов задан в функции `Префикс()` — по умолчанию `МФ_`. Если в конфигурации префикс уже занят, поменяйте его там, в одном месте.

## Порядок работы

1. Реквизиты: `СоздатьРеквизит` (один) или `СоздатьРеквизиты` (пакет, один вызов `ИзменитьРеквизиты`).
2. Элементы: `СоздатьГруппу`, `СоздатьПолеВвода`, `СоздатьТаблицу`, `СоздатьКолонку`, `СоздатьКнопку`.
3. Всё это — в `ПриСозданииНаСервере`. В `ПриОткрытии` и позже платформа запрещает менять состав формы.

```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)

    Скидка = МФ_МодификацияФорм.ИмяСПрефиксом("Скидка");      // "МФ_Скидка"
    Расчёт = МФ_МодификацияФорм.ИмяСПрефиксом("Расчёт");

    Описания = Новый Массив;
    Описания.Добавить(МФ_МодификацияФорм.ОписаниеРеквизита(Скидка,
        МФ_МодификацияФорм.ОписаниеТипаЧисло(5, 2)));
    Описания.Добавить(МФ_МодификацияФорм.ОписаниеРеквизита(Расчёт,
        МФ_МодификацияФорм.ОписаниеТипаТаблицаЗначений(), "", "",
        Новый Структура("Товар, Сумма",
            МФ_МодификацияФорм.ОписаниеТипаСтрока(100),
            МФ_МодификацияФорм.ОписаниеТипаЧисло(15, 2))));
    МФ_МодификацияФорм.СоздатьРеквизиты(ЭтотОбъект, Описания);

    Группа = МФ_МодификацияФорм.СоздатьГруппуКонтейнер(ЭтотОбъект,
        МФ_МодификацияФорм.ИмяСПрефиксом("ГруппаРасчёт"));
    МФ_МодификацияФорм.СоздатьПолеВвода(ЭтотОбъект, Скидка, Скидка, Группа, "Скидка, %");

    МФ_МодификацияФорм.СоздатьТаблицу(ЭтотОбъект, Расчёт, Расчёт, Группа, "Расчёт");
    МФ_МодификацияФорм.СоздатьКолонку(ЭтотОбъект, Расчёт, "Товар", "Товар");
    МФ_МодификацияФорм.СоздатьКолонку(ЭтотОбъект, Расчёт, "Сумма", "Сумма",
        ВидПоляФормы.ПолеНадписи);

КонецПроцедуры
```

## Как выбирать метод

| Задача | Метод |
|---|---|
| Один реквизит | `СоздатьРеквизит` |
| Два и больше | `СоздатьРеквизиты` с массивом `ОписаниеРеквизита` |
| Нужен свой контроль массива | `ДобавитьРеквизит` + `ПрименитьРеквизиты` |
| Реквизит-таблица с выводом на форму | `СоздатьТаблицуСКолонками` |
| Поле, флажок, надпись, переключатель | `СоздатьПолеВвода`, `СоздатьПолеФлажка`, `СоздатьПолеНадписи`, `СоздатьПолеПереключателя` |
| Нестандартный элемент, нужны `ВставитьПеред` и `Свойства` | `СоздатьЭлемент` |

## Правила дизайна

- Обязательные параметры идут первыми. Обязательны те, без которых результат бессмыслен: `Форма`, `Имя`, `ПутьКДанным` у поля и таблицы, `ИмяКоманды` у кнопки, `Действие` у команды.
- Скрытых решений нет. Единственное умолчание — `СоздатьКнопку` без родителя ставит кнопку в командную панель формы; это описано в её документации.
- Все `Создать*` идемпотентны: если элемент с таким именем уже есть, метод вернёт его, не меняя.
- Свойства и события применяются последними, поэтому переданная структура перекрывает умолчания.

## Проверено

Прогон на живой базе (платформа 8.5.1.1529, тонкий клиент): 48 проверок, все 43 экспортных метода, ошибок нет. Синтаксический контроль конфигурации — чистый.

Что прогон ловит на практике. Почти все ошибки, найденные при первой проверке, оказались одного класса: метод присваивал значение входному параметру. Если в такой параметр передан элемент формы, платформа связывает параметр со свойством формы, и присваивание падает с «Поле объекта недоступно для записи». Сейчас входные параметры только читаются, значения по умолчанию считаются в локальные переменные.

## Ограничения платформы, которые модуль не обходит

- Реквизит формы живёт, пока открыта форма. Нужно хранение — реквизит объекта или регистр.
- Колонка в пути `Объект.Товары` существует только в данных формы: при перечитывании объекта теряется.
- Программный реквизит в таблице с типом `РегистрБухгалтерииНаборЗаписей` / `РегистрНакопленияНаборЗаписей` сбивает пути колонок этой таблицы (ошибка платформы). Держите отдельную таблицу значений.
- Удаляются только программно созданные реквизиты и элементы. Созданное в конфигураторе скрывается свойством `Видимость`.
